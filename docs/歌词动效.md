# 歌词动效：唱到哪个字，哪个字才落下

片子里的歌词不是字幕，是版面的一部分：大号明朝体竖排压在画面一侧、方块字一格一格翻出来、说明栏一样的歌词条。所有版式遵守同一条规则：**每个字在它被唱出来的那一刻落下**，落下时略微放大再弹回原大，画面可以比声音早一帧，不能晚。

## 1. 时间数据

每个字的时间存在 `web/data/lyrics.json`（页面读的文件）。仓库里**不带歌词文本**，只带时间：[web/data/lyrics_timing.json](../web/data/lyrics_timing.json)。用自己的歌词合成页面要的文件：

```powershell
# input/lyrics_lines.txt：片中用到的 44 句，一句一行，按片中顺序
python src/apply_lyrics.py        # -> web/data/lyrics.json
```

`lyrics_timing.json` 每一句是：

```json
{ "t0": 35.694, "end": 39.113, "n": 7,
  "t":    [35.694, 35.913, 36.352, 36.771, 37.205, 38.059, 38.453],
  "file": [35.698, 35.948, 36.408, 36.818, 37.258, 38.068, 38.498] }
```

- `t`：这个字在画面上落下的秒数（歌曲时间，从音频文件开头算）；
- `file`：卡拉 OK 轴原来给的时间，`null` 表示这个字不单独唱（全角空格、括号、促音），它跟着邻字出现；
- 每个字都有自己的时间，全角空格也算一个字，所以 `input/lyrics_lines.txt` 每一行的字数必须等于 `n`，脚本会逐行核对。合成后的格式见 [web/data/lyrics.example.json](../web/data/lyrics.example.json)（占位文字，不是歌词）。

### 时间是怎么量出来的

卡拉 OK 轴是人耳打的，平均晚了约 1/20 秒，而且早晚不均。[src/lyric_timing.py](../src/lyric_timing.py) 在**分离出来的人声**上把每个音节挪到最近的起音点：

1. 用 demucs 分出人声（`input/vocals.wav`）；
2. librosa 算起音强度、挑峰值（hop 110，约 5 ms 一格）；
3. 每个音节在 [卡拉OK时间 − 0.17 s, + 0.07 s] 里找最近的起音，找到就用它；人声没有清楚起音的（连着前一个音唱的），用卡拉 OK 时间减去平均晚的 0.05 s；
4. 一个字占几个音节写在 `input/lyric_syllables.txt` 里（例如 `学2` 表示这个字唱了两个音节），字的时间取它的第一个音节；不单独唱的字写 `0`：开括号和空格跟下一个字一起出现，其他（闭括号、问号、省略号）在前一个字之后 0.12 秒出现。

脚本会打印每个字被挪了多少，以及“挪到起音上的音节数 / 保留原时间的音节数”，方便核对。卡拉 OK 轴和你手里的音频之间如果有整体偏移，写在 `input/timing.json` 的 `ass_offset_seconds` 里（本片用的轴比母带晚了 0.8822 秒）。

> 最后的标准是耳朵：逐句对着歌听，按歌手真实的断句出字，不要整句预先显示。

## 2. 出字的函数（`web/pages/kit.js`）

```js
const L = { a: line('……') };         // 按文本找到这一句，返回 [{c, t}]，空格不画
column(c, L.a, T, x, y0, size, o);    // 竖排：从 (x, y0) 往下，每个字唱到才出现
row(c, L.a, T, x0, y, size, o);       // 横排：逐字量宽度往右排，返回整行宽度
```

- **落下的动作**：`hit(age, amt, rate)` —— 唱之前是 0（不画）；唱的那一刻放大 `1 + amt`，按 `exp(-age·rate)` 回到原大。默认 `amt = 0.28`、`rate = 16`，大约 0.2 秒落定。所有版式共用它，所以全片的字“落”的手感一致。
- **竖排的细节**（`column()`）：小假名（っゃゅょ…）往右上挪 0.1 个字身；「」ー（）转 90°；行距默认 1.06 个字身。know 页自己的 `vcol()` 再加两条：小假名缩到 70%，每个字带一圈底色描边（压在书架上也读得清）。
- **横排的细节**（`row()`）：每个字先 `measureText` 量宽度再放，`track` 加字距，所以不同字体、不同字号都不会挤在一起或留出空洞。
- `?clean=1`：页面不画歌词（做无字的画面时用）。

## 4. 排版规则（每一页都过）

1. **先量再放**：字的位置由 `measureText` 量出的宽度和字号推出来，不写死某个字的坐标；改了字号或字体，整行跟着重排。
2. **不压人**：字不压脸、不压蝴蝶结，不被飞的纸盖住，也不互相重叠。verse2 结尾飞出去的纸先检查会不会穿过她的脸，会就改成从她身后走（见 [记忆涌出](记忆涌出.md)）。
3. **离四边至少 60 px**，不被画框切掉。
4. **竖排从右往左读**，顺序要对；括号和长音转 90°。
5. **只出日文歌词和日文 / 英文界面标签**，不出现中文。
6. **不在拍上出现的东西不出现**：字唱到才落，翻页、盖章、数字跳动也都落在拍或半拍上（见 [按拍对点](按拍对点.md)）。

## 5. 想复用到别的歌

- 时间数据换成你的歌：先打卡拉 OK 轴（或从 LRC 起步），再用 `lyric_timing.py` 的方法在人声上修正；
- `kit.js` 的 `line()` 按文本找句子，所以页面里写的句子要和 `lyrics.json` 的 `text` 一致（去掉空格后比较）；
- 版式本身和这首歌无关，`column()`、`row()`、`hit()` 可以直接拿走。

## 「アリガトウ」的重复

每句唱四遍，两遍一组。人工以 0.25 倍速跟人声分轨打拍，再用第一遍扣除按键延迟，得到 `kit.js` 里的 `ARI_T`。每次仍沿用第一遍的五个音节间隔。旧版 `echoTimes()` 按固定拍距重打。v12 用 `ariReps()` 读入实际打拍时间，由 `stampOf()` 找出当前的敲击，画面在原位逐格重打、瞬间反色并扩出一圈边框。歌里唱了几遍，屏幕上就出几遍，不用省略号代替。
