# 按拍对点：换张、切镜、出字都落在拍上

人物换一张图、镜头切一刀、盖一个章、翻一页、落一个字，都必须落在拍点或半拍上。主角是画面中心的时候尤其要卡准，观众会在换张的那一下“听到”画面。这一篇讲拍点从哪来、页面怎么写、写完怎么检查。

## 1. 拍点网格

全片只有一条固定的网格：

```text
第 k 拍 = 20.016 + k × 0.42858 秒      （140 BPM；k 能被 4 整除的是小节线）
```

它是用 [tools/beat_grid.py](../tools/beat_grid.py) 在音频上量出来的（只用 numpy）：

1. 算频谱通量起音曲线，全频段一条、底鼓频段（30–160 Hz）一条；
2. 梳状滤波找速度：曲线隔 1、2、4、8、16 个周期最像自己的那个周期（各段都在 139.94 BPM 附近）；
3. 在 140 BPM 附近细扫周期和相位，让网格点落在起音最强的位置（底鼓权重加倍），得到周期 0.42858 s、第 0 拍在 20.016 s；
4. 按“拍在小节里的位置”统计底鼓强度找小节线，再把第一段副歌每一拍和每个半拍的强度列出来。

**后半段的重音在半拍上。** 本曲从 k ≈ 333.5 开始，人声多数落在 x.5 拍；第一段副歌奔跑那段（k 206–224），底鼓按拍内相位统计也是半拍处最强。所以这些段落的换张、落脚都放在 k + 0.5，而不是整拍。判断标准是耳朵听到的“咚”在哪，不是网格本身。

本曲开头约 8 秒的八音盒不在网格上，开场那几秒按实测的音头对。

## 2. 页面里怎么写

每一页是一个 ES 模块：`export const name, start, duration; export async function prepare(); export function draw(c, t)`。`start` 用拍号写（`kt(36)`），`draw` 里把时间换回拍号再判断：

```js
const T0B = 20.016, PB = 0.42858, kt = k => T0B + k * PB, kbOf = T => (T - T0B) / PB;
export const start = kt(36);
export const duration = kt(99.5) - start;
```

人物的表演写成“从第几拍起换成哪一张”的表，一张接一张、不回头：

```js
// verse1：放下她、看我们；第 47 拍眼睛转向他；第 50 拍盖章，眼睛落到章上
const B_SEQ = [[44, 'hi0'], [47, 'hi_l'], [50, 'hi_d']];
const pickK = (A, kb) => { let n = A[0][1]; for (const [k, v] of A) if (kb >= k - 1e-6) n = v; return n; };
fig(c, pickK(B_SEQ, kbOf(T)), x, y, h);
```

表里的卡片名后面加 `~`，表示这个姿势停留期间播风的循环（[连贯动作](连贯动作.md)）。

### 换张的规矩

1. **每张至少停两拍**（0.857 秒）。停不满两拍的普通换张读起来像抽搐。
2. **不许 A→B→A**：一个位置上的图不能换过去又换回来（那就是“鬼畜”）；4 秒内 A→B→C→A 也算。
3. 例外是**画出来的循环**（走、跑、风、泪）：它们每张只停 2–3 帧，是一个整体的动作，单独审。
4. 他变老这件事全片只讲一次（ages 页），其余地方不用“一张张变老”当过渡。

## 3. 画面早声音一帧

合成时画面整体比声音早一帧（[src/assemble_pages.py](../src/assemble_pages.py) 的 `LEAD = 1/24`）：为第 k 拍画的变化，在那一拍响起时已经在屏幕上了，而不是晚一帧。奔跑的落脚张也按这个原则提前一帧（`chorus1.js` 的 `LEAD`）。

## 4. 截帧和合成

```powershell
python web/serve.py                       # 预览服务（端口 8765），也负责把页面发回来的 PNG 存进 frames/
node tools/render.mjs "page=know&t=2,5.5" # 单帧：frames/know_t2_00.png、frames/know_t5_50.png
python tools/capture_all.py know chorus1  # 整页逐帧：frames/<页>/f%05d.png，24 fps
python src/assemble_pages.py out.mp4      # 按歌曲时间把 11 页接成一条，配上 input/kokoro.wav
```

- [tools/render.mjs](../tools/render.mjs) 每次起一个**自己的**无头 Chrome（独立的用户目录和调试端口），打开 `page.html?page=…`，等页面把 `window.film.done` 设为真；页面报错就返回 1。结束时先让浏览器自己关闭，再按这次的用户目录名找出残留的 Chrome 进程结束掉（曾经因为只结束启动器、真正的浏览器留在后台，堆了几百个进程）。
- [tools/capture_all.py](../tools/capture_all.py) 把每页切成 10 秒一段截，每段最多重试 4 次、每次 **4 分钟超时**（一次 Chrome 卡死曾让整个截帧停了一个小时）。
- 页面表（页名和它在歌里开始的秒数）在 `capture_all.py` 和 `assemble_pages.py` 里各有一份，两份要一致。合成时缺帧会打印 `MISSING`；一页最后一帧因为取整多用一帧是正常的。
- **渲染和烘焙不能同时进行**：渲染可能读到还没写完的卡片。所有出图和烘焙结束后，统一重截一遍再合成。

## 5. 检查

### 换张审计：每一帧画了哪些卡

```powershell
node tools/audit_swaps.mjs know          # 记录：frames/audit/cards_know.json
python tools/audit_swaps.py              # 分析：需要 11 页的记录都在
```

[tools/audit_swaps_probe.js](../tools/audit_swaps_probe.js) 在浏览器里加载页面模块，按 24 fps 一帧帧调用 `draw()`，同时拦截 `drawImage`（包括画进离屏画布再画回来的、剪影着色的）和 three.js 平面的渲染回调，记下每一帧每张人物卡片画在画面的哪个框里、透明度多少。像素照常画，只是多记了账。

[tools/audit_swaps.py](../tools/audit_swaps.py) 把相邻帧里重叠的框连成“槽位”（画面上同一个人的位置），再看每个槽位里卡片的先后：

| 类型 | 含义 |
|---|---|
| `short` | 一张图停不满两拍就被换掉 |
| `inb` | 只停 1–3 帧（中间张、眨眼），单独列出 |
| `aba` / `aba_blink` | A→B→A |
| `back2` | 4 秒内 A→B→C→A |
| `wind` / `aba_wind` | 风循环的换张（豁免） |
| `ageing` | 他的不同年龄互相替换的位置（应该只在 ages 页） |

走路、奔跑循环自动豁免；每条报警都附上页面代码里引用这张卡的行号，直接跳过去改。审计报的是“画面上的槽位”，偶尔会把从人物身后飞过的小图并进她的槽位，报出来的要对着画面确认。

### 同步检查：成片的画面变化是不是落在拍上

```powershell
python tools/sync_check.py out.mp4
```

[tools/sync_check.py](../tools/sync_check.py) 在**成片文件**上量，不看页面代码：把每帧缩成 96×54 的灰度图，算相邻帧的差，取变化最大的 8%（切镜、换张、盖章），统计它们离最近的半拍 / 整拍有多远，以及平均偏移（负数 = 画面早于拍点）。
