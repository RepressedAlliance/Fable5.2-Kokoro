# 踩过的坑

每条写三件事：看到了什么、为什么会这样、现在怎么做。按“做一支类似的片子最可能再踩”的顺序排。

## 人物图

**1. 拼贴像素：锯齿、残留底色、脚朝反了。**
成因：为了让换张时凳子、桌子和人物身体逐像素不动，把设定图里凳桌的像素贴回去、把别张的腿接过来、把人整块贴进双人图。每一处接缝都是抠图边，接上的腿方向和身体对不上。
现在：一张卡就是 Codex 一次整张生成，人和她碰到的东西画在同一张图里；后期只抠底、清边。“同一把凳子”靠设定图做参考来保证，不要求逐像素相同。

**2. 用量出来的数验收，没问题的图被判成有问题。**
成因：“上臂短 15%”“头大 6%”这类数字既会误杀看着自然的图，也会放过数字合格、一眼看去很怪的图。骨架和量值逼出来的姿势也僵。
现在：验收只问“观众一眼看过去怪不怪”，每张单图给 gpt-6-astra 看；量值脚本只用来定位问题。

**3. 道具没有设定图，各画各的。**
成因：凳子、桌子只用文字描述，模型每张自己发挥：腿数不同、桌面倾斜，桌上的纸跟着歪。
现在：先做道具三视图（先用脚本画几何引导图，再让 Codex 上片中画法），凡是画到道具的卡片都带上它。报告这种有正反面、有方向的道具同样要有设定图。

**4. 两个人画得一样高，手又短又小。**
成因：提示词没写身高差，模型默认两人等高；仰视的手臂放进平面版式里，会被读成画错。
现在：角色段落写明身高（她 152 cm、他 179 cm，“nearly a head taller”），双人图写清谁弯腰、头在谁旁边；抬手类的图和母版并排看手臂长度。

**5. 换了画幅，比例跟着变。**
成因：母版是不常见的画幅时，模型常常按另一个画幅回图，人物比例随之改变。
现在：参考图先垫成模型常用的画幅（`tools/pad_ref.py`），提示词写死像素尺寸；烘焙时原样裁回。

**6. 纸的哪一面朝观众，前后矛盾。**
成因：只写了“拿着报告”，没写正反面。人在读纸时，朝观众的应该是空白的纸背；递给别人时，标题那一端朝着接纸的人。
现在：提示词写清哪一面朝谁、标题在哪一端、手怎么托（见 [提示词](提示词.md) 的 `PAPER`）。

**7. 泪和眼睛被涂成了纸色。**
成因：烘焙把平涂的浅青色当作纸换成米白，瞳孔的高光和泪也是浅青色。
现在：`sets.json` 里写 `paper_min`，只有纸那么大的浅青色块才算纸（[人物图怎么不出错](人物图怎么不出错.md)）。

**8. 用代码往图上加泪、加光圈，显得廉价。**
成因：代码画的泪和手绘线条不是一种画法，贴在脸上像贴纸；眼睛换了张，泪还留在原处。
现在：泪、纸上的报告都画进 Codex 的整张图里；动态的泪是一组画出来的帧（[连贯动作](连贯动作.md)）。

## 动作和节奏

**9. 循环只有两张，来回切成了“鬼畜”。**
成因：A→B→A 两张交替，眼睛读到的是闪烁，不是动作。
现在：循环至少四个相位，每两个相位之间画中间张，一圈回到起点是顺的；普通换张每张至少停两拍、不回头。`tools/audit_swaps.py` 专门抓这两类。

**10. 为了不鬼畜，又改得太保守，看不出在动。**
成因：把一句批评当成了“少动”，而不是“动得不对”。
现在：先找一镜大家都认可的作为标准（本片是 know 页背对镜头走路的那一镜），其余动态做到它的连贯程度，幅度要看得出来。

**11. 把一句批评放大成全片规则，动态被砍没了。**
成因：针对某一镜的意见，被当成适用于全片的硬规则执行，连原本被认可的效果也改掉了。
现在：意见先归到它说的那一镜和那一类问题；被认可过的效果不当错误去“修”；拿不准的地方先问清标准再动手。

**12. 越跑越快和歌不搭。**
成因：用画面加速表达“加速する鼓動”，但脚步和节奏脱开了。
现在：步频恒定、一拍一步、落脚卡在重音上；要表达加速，就让数字（BPM 计数）去涨。

**13. 换张卡在网格上，却没卡在听到的“咚”上。**
成因：后半段的人声和底鼓落在半拍上，整拍处反而弱。
现在：按段落量重音的相位（`tools/beat_grid.py`），换张放在耳朵听到的位置；画面比声音早一帧。

## 画面

**14. 给旧镜头加一个框，就当成重新设计。**
成因：省事，但观众看到的还是同一个镜头。
现在：每一段从“这一句要讲什么事”重新设计版面，不借旧镜头、不套壳。

**15. 小人放在大片空画面中间，视觉中心散了。**
成因：先摆了场景再放人，人物只占画面一小块。
现在：先定画面和视觉中心，再摆机位；人物全身入画时至少占画面高度的一半。

**16. 随手放的符号（！、？）飘在空处。**
成因：为了“有点动静”往空白处加符号。
现在：画面里的每样东西都要有来处，空着就空着，或者重新构图。

## 流程和工具

**17. 代理的报告说“已完成”，文件却不对。**
成因：报告是文字，可能写的是计划而不是结果，也可能漏掉并发写坏的地方。
现在：每次交回都用实际文件核对：卡片 PNG 的尺寸等于 `v2.json` 的 `px`、页面能渲染、帧是新的。看图的结论也是模型给的，只当线索，放行前自己再看一遍。

**18. 并发烘焙互相覆盖，渲染读到写了一半的图。**
成因：几组同时写同一个 `v2.json`；渲染和烘焙同时进行，读到正在写的 PNG（画面里人物的腿突然没了）。
现在：烘焙加锁、一次一组；所有烘焙结束、所有页面空闲之后，统一重截一遍再合成。

**19. 截帧卡死，后台堆了几百个 Chrome。**
成因：一次 Chrome 卡住让整个截帧停了一小时；只结束启动器进程时，真正的浏览器和它的子进程留在后台。
现在：每段截帧 4 分钟超时、重试；`render.mjs` 每次用独立的用户目录，结束时先让浏览器自己关闭，再按用户目录名清掉残留进程。

**20. 断网就渲染失败。**
成因：three.js 从 CDN 加载。
现在：`web/vendor/three.module.js` 放在本地（r170，MIT）。

**21. Windows 的文件名不分大小写，一组图被悄悄覆盖。**
成因：`d3` 和 `D3` 在 Windows 上是同一个文件，生成脚本遇到“已存在”就跳过，结果少了一组。
现在：起名前先查重，生成后核对数量。

**22. 带着已知的不足交片，被退回。**
成因：想着“小问题先交了再说”。
现在：自己的不足清单清空、审片没有严重问题，才交给别人看；一时修不了的，如实写在清单里。

## 歌词结束早于人声

旧时间轴到「永遠に歌う」就结束。用人声分轨从头核对到最后一个唱音。faster-whisper 逐字识别和 torchaudio MMS 强制对齐都没能分开主唱与和声的重复，最后用慢速人工打拍。

## 道具上的印刷要跟着纸转

报告旋转时，纸上的「心」和其他印刷应随同一张纸一起变换。把印刷放在纸面坐标里，避免纸已经转过去、字还正对镜头。
